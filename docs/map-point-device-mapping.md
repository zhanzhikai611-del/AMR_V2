# 地图点位与 CNC 映射说明

## 关系定义

地图站点表示 AMR 可以到达的物理位置，设备或设施表示当前共同区域内可与站点建立业务关系的资源。二者通过稳定标识建立映射：

`地图站点 stationUid / stationName → deviceId`。

映射只保存站点与设备的关联关系，不保存设备的在线、加工、充电或报警等实时状态。

## 推荐字段

```json
{
  "stationUid": "2824607688",
  "stationName": "D16",
  "deviceId": "D16",
  "enabled": true
}
```

- `stationUid`：站点稳定标识，使用字符串保存，避免无符号整数兼容问题。
- `stationName`：便于操作员识别的站点名称，不作为唯一关联键。
- `deviceId`：当前共同区域内的设备或设施编号，可以是 CNC、充电设备、缓存位等资源。
- `enabled`：是否启用该映射。

## 编辑器交互

地图编辑器选中站点后，在属性面板提供“站点用途”区域。用户只面对普通导航点、设备对接点、充电点、Home/停车点四种用途；后三种分别对应 `dockable`、`charged`、`parkable`。选择特殊用途后，再从当前共同区域内选择对应设备。第一版不提供上料、下料等允许动作配置，具体任务动作由派单系统负责。

属性面板按使用频率分组：默认展开“基本信息”“位置与朝向”“关联设备”，折叠“车端扩展属性”“系统信息”。名称和别名可编辑，UID 与所属地图只读；朝向用角度编辑、内部仍保存弧度。禁用状态放在站点摘要旁，便于现场人员快速识别。

地图编辑器不设置底部状态栏，画布延伸至窗口底部；保存状态与地图校验结果统一由顶部操作区反馈。

## 密集机台区域的编辑器呈现

当前地图编辑器原型以 SLAM 点云底图叠加路网，不再提供底图、逻辑图与叠加图切换。编辑画布支持滚轮缩放、拖动平移、适应视图以及点位和路线定位；实时监控地图暂不随本轮原型调整。

密集 CNC 区域按以下现场语义绘制：

- 点云图中的黑色设备轮廓视为生产设备区域，橙色三角形表示 AMR 在一拖二机械手臂侧实际停车并执行操作的服务点。
- 三角形必须位于可通行路线上，不得覆盖设备轮廓；纵向停靠点默认朝上。
- 有两侧设备服务面的纵向通道使用两条平行路线；只有单排设备或单侧服务面的区域只使用一条路线。
- 双线通道中的 X 形路线由左右两侧相邻站点交叉连接，两条斜线均按普通直线路线保存。
- 没有成排服务点的中部横向通道和底部回车通道使用单线，并在需要表达停靠或方向的位置显示三角点。
- 路线必须沿点云中的实际通道和墙体缺口布置，不得穿过黑色设备轮廓或墙体；右侧未确认的下部区域暂不建立路线。
- 用户侧统一使用“站点”概念：设备停靠点、转弯点、路口点和路线衔接点都是可导航站点，当前原型全部使用三角形显示。

上述坐标与路线数量目前用于验证密集现场的编辑体验，后续导入真实地图时应由现场标定数据替换，不应把原型坐标作为自动识别结果。

## 当前前端原型边界

当前阶段由产品原型验证地图查看与编辑方式。编辑器保留“保存草稿”和“发布地图”入口，但不提供独立的“校验地图”操作；发布时自动执行检查，存在错误时弹窗阻止发布，只有警告时允许用户确认继续。车端异步下发仍只定义产品规则，不在当前前端原型中实现。

后续正式系统需要补充以下产品规则，但不属于当前原型验收范围：

- 发布前校验站点名称与 UID、路线端点引用、重复路线、孤立站点、路网可达性以及 CNC 服务站点映射。
- 保存草稿不得影响 AMR 当前运行地图；校验通过后生成不可变的新地图版本。
- 新版本采用异步下发，AMR 有任务、未停止、离线或处于上下料、充电、异常恢复状态时保持等待。
- 第一阶段按整张地图下发，不处理增量合并；车辆加载并完成重定位后回报实际生效版本。
- 单车下发失败不得影响其他车辆，也不得破坏该车辆原有地图；正式系统应支持失败重试和版本回退。
- 实时监控始终使用车辆当前已生效的地图，不提前展示尚未完成下发的新版本。

绘制管制区属于当前地图编辑器原型范围。用户可在画布上通过两个角点建立矩形区域，并设置互斥区、限速区或禁行区；具体调度执行规则待后端和车端能力确认后实现。

一个设备可以对应多个站点，例如上料位、下料位和安全交接位；一个站点默认只绑定一个设备。若现场确实存在共享交接位，再显式允许一对多并设置任务互斥。

E08、E10 当前对应人工上料位置。两个站点仍保留地图点位和标签，但不建立 AMR 自动服务关系；地图不显示 AMR 服务编号。AMR-05、AMR-06 详情仍在完整服务范围中展示这两个站点，并以置灰标签表示人工上料、不可自动服务。

运行时流程为：设备上报请求 → 系统通过 `deviceId` 找到关联站点 → 调度 AMR 到达该站点 → 派单系统继续执行对应任务流程。设备在线状态、加工状态和握手信号仍由设备接入层维护。
