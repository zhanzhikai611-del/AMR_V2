# 地图点位与 CNC 映射说明

## 关系定义

地图站点表示 AMR 可以到达的物理位置，设备或设施表示当前共同区域内可与站点建立业务关系的资源。二者通过稳定标识建立映射：

`地图站点 stationUid / stationName → deviceId`。

映射只保存站点与设备的关联关系，不保存设备的在线、加工、充电或报警等实时状态。

## 推荐字段

```json
{
  "stationUid": "2824607688",
  "stationName": "D16",
  "deviceId": "D16",
  "enabled": true
}
```

- `stationUid`：站点稳定标识，使用字符串保存，避免无符号整数兼容问题。
- `stationName`：便于操作员识别的站点名称，不作为唯一关联键。
- `deviceId`：当前共同区域内的设备或设施编号，可以是 CNC、充电设备、缓存位等资源。
- `enabled`：是否启用该映射。

## 编辑器交互

地图编辑器选中站点后，在属性面板提供“站点用途”区域。用户只面对普通导航点、设备对接点、充电点、Home/停车点四种用途；后三种分别对应 `dockable`、`charged`、`parkable`。选择特殊用途后，再从当前共同区域内选择对应设备。第一版不提供上料、下料等允许动作配置，具体任务动作由派单系统负责。

属性面板按使用频率分组：默认展开“基本信息”“位置与朝向”“关联设备”，折叠“车端扩展属性”“系统信息”。名称和别名可编辑，UID 与所属地图只读；朝向用角度编辑、内部仍保存弧度。禁用状态放在站点摘要旁，便于现场人员快速识别。

地图编辑器不设置底部状态栏，画布延伸至窗口底部；保存状态与地图校验结果统一由顶部操作区反馈。

## 密集机台区域的编辑器呈现

当前地图编辑器原型以 SLAM 点云底图叠加路网，不再提供底图、逻辑图与叠加图切换。编辑画布支持滚轮缩放、拖动平移、适应视图以及点位和路线定位。实时监控已复用相同底图组件、绘制坐标和站点路网数据，独立提供只读图层入口。

密集 CNC 区域按以下现场语义绘制：

- 点云图中的黑色设备轮廓视为生产设备区域，橙色三角形表示 AMR 在一拖二机械手臂侧实际停车并执行操作的服务点。
- 三角形必须位于可通行路线上，不得覆盖设备轮廓；纵向停靠点默认朝上。
- 有两侧设备服务面的纵向通道使用两条平行路线；只有单排设备或单侧服务面的区域只使用一条路线。
- 双线通道中的 X 形路线由左右两侧相邻站点交叉连接，两条斜线均按普通直线路线保存。
- 没有成排服务点的中部横向通道和底部回车通道使用单线，并在需要表达停靠或方向的位置显示三角点。
- 路线必须沿点云中的实际通道和墙体缺口布置，不得穿过黑色设备轮廓或墙体；右侧未确认的下部区域暂不建立路线。
- 用户侧统一使用“站点”概念：设备停靠点、转弯点、路口点和路线衔接点都是可导航站点，当前原型全部使用三角形显示。

上述坐标与路线数量目前用于验证密集现场的编辑体验，后续导入真实地图时应由现场标定数据替换，不应把原型坐标作为自动识别结果。

## 当前前端原型边界

### 实时监控地图迁移（2026-08-31）

- 监控右上角“图层”可分别控制点云地图、路线、设备站点、一般站点、停车点、充电点、设备名称。一般站点、停车点和充电点各自独立开关，默认隐藏；隐藏站点不删除路线端点，车辆和选中任务路径不受图层开关影响。
- 保留 AMR 图标选择入口，继续联动任务、服务范围及右侧详情；设备标签不再展示车辆编号。“收起”保留选择，“关闭”清除选择。E08、E10 仍无自动服务编号，并在车辆完整服务范围中置灰。
- 地图管理缩略图改为读取该版本的实际站点和路线，不再绘制固定规则网格；逻辑对象数量按加载的数据计算。
- 原型设备映射统一保存在 `mock/data/map-device-bindings.ts`。120 个设备站点一一绑定 120 个唯一设备，均有设备标签。保留原有 D02～D24、C02～C24、E02～E24 的标识与站点绑定，其余站点按所属组补充偶数编号至 80。此映射只用于演示，不是现场标定结果。
- 基础配对按相邻通道分为三组，各 40 个设备：D 组为 A1-L/A1-R/A2-L/A2-R/A3-L，由 AMR-01/02 共同服务；C 组为 A3-R/A4-L/A4-R/A5-L/A5-R，由 AMR-03/04 共同服务；E 组为 A6-L/A6-R/A7-L/A7-R/A8-R，由 AMR-05/06 共同服务。支持跨组共享：当前演示 D04 由 01/02/03 服务，C04 由 01/02/03/04/05 服务，E04 由全部六台服务；这些示例不是调度任务分配，也不限制每台设备的服务车辆数量。E08、E10 保留设备标签与完整服务范围，但排除自动服务。设备列表、编辑器、监控和派单共用这套映射。
- 标签仅显示设备名称，不展示 AMR 编号。同一行相距不超过10个地图单位的相邻站点成对排列：左标签向左上方展开，右标签向右上方展开，保持同一高度；独立站点标签居中放在正上方。短引线分别连接标签靠近站点的底角，独立标签连接底边中点；遇到遮挡时整对向上避让，不互换左右位置。仅悬停设备名称或站点时，同步突出站点、引线和标签；移开即恢复，不支持点击选中或固定高亮，且不覆盖车辆选择上下文。标签保持深蓝底白字，选中车辆的服务设备通过细亮边和局部蓝色微光点亮；悬停再提高一档亮度，不放大、不闪烁。站点三角形同步微光，引线使用中性灰细线，无白色衬线，悬停只加深，不变蓝、不加粗、不发光；基础路线采用1.5px蓝灰线，与引线区分；站点和引线均不显示圆圈，设备状态不映射成红色。无关设备适度降低对比，仍保留名称可读性。
- 标签布局不依赖车辆动画坐标，避免车辆运动导致标签跳动。极端密度下标签列可延伸到地图外留白，通过平移、缩放查看，不隐藏设备。地图左上角不再显示区域名称、版本及演示标识块，仅保留任务路径图例。
- 设备状态本身不改变站点颜色；颜色只表达实时任务语义。执行中任务的目标设备站点及标签以蓝色微光点亮，异常任务的目标设备站点及标签显示红色告警。待执行任务不点亮；异常红色优先于车辆服务范围和悬停高亮。
- `npm run test:station-labels` 验证全部120个设备标签、标签与站点不重叠、锚点对应关系、布局顺序稳定，以及服务车辆数量变化不影响名称布局；当前页面仍保持六台示例车辆，未为测试虚构额外车辆资产。
- `mock/data/runtime-map.ts` 从当前已发布版本复制运行地图，沿其实际路线生成演示路径；该过程不在地图组件内执行，也不会将草稿保存或发布到实际车辆。
- 运行快照新增 `runtimeMap`（地图版本、名称、站点、路线及演示标记）与 `simulation` 字段。当前点云资源和绘制框仍对应仓库内的示例地图；接入其他现场地图时须补充每版本底图资源、分辨率、原点与坐标转换，不能复用示例标定。
- 非演示快照不模拟车辆运动，直接绘制上报位置、规划路径和已走路径。未提供运行地图时明确显示提示，不回退到旧规则网格；正式后端接入须提供车辆已生效版本的快照。
- 为密集地图补充滚轮缩放、缩放按钮与适应地图。详情展开时保留绘制比例，并仅在选中车辆不在可见范围时调整视野；不会持续追踪车辆打断手动平移。

当前阶段由产品原型验证地图查看与编辑方式。编辑器保留“保存草稿”和“发布地图”入口，但不提供独立的“校验地图”操作；发布时自动执行检查，存在错误时弹窗阻止发布，只有警告时允许用户确认继续。车端异步下发仍只定义产品规则，不在当前前端原型中实现。

后续正式系统需要补充以下产品规则，但不属于当前原型验收范围：

- 发布前校验站点名称与 UID、路线端点引用、重复路线、孤立站点、路网可达性以及 CNC 服务站点映射。
- 保存草稿不得影响 AMR 当前运行地图；校验通过后生成不可变的新地图版本。
- 新版本采用异步下发，AMR 有任务、未停止、离线或处于上下料、充电、异常恢复状态时保持等待。
- 第一阶段按整张地图下发，不处理增量合并；车辆加载并完成重定位后回报实际生效版本。
- 单车下发失败不得影响其他车辆，也不得破坏该车辆原有地图；正式系统应支持失败重试和版本回退。
- 实时监控始终使用车辆当前已生效的地图，不提前展示尚未完成下发的新版本。

绘制管制区属于当前地图编辑器原型范围。用户可在画布上通过两个角点建立矩形区域，并设置互斥区、限速区或禁行区；具体调度执行规则待后端和车端能力确认后实现。

一个设备可以对应多个站点，例如上料位、下料位和安全交接位；一个站点默认只绑定一个设备。若现场确实存在共享交接位，再显式允许一对多并设置任务互斥。

E08、E10 当前对应人工上料位置。两个站点仍保留地图点位和标签，但不建立 AMR 自动服务关系；地图不显示 AMR 服务编号。AMR-05、AMR-06 详情仍在完整服务范围中展示这两个站点，并以置灰标签表示人工上料、不可自动服务。

运行时流程为：设备上报请求 → 系统通过 `deviceId` 找到关联站点 → 调度 AMR 到达该站点 → 派单系统继续执行对应任务流程。设备在线状态、加工状态和握手信号仍由设备接入层维护。
