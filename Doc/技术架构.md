## 1. 文档目的

本文档记录 AMR_v2 的前端技术边界、工程结构、数据流、接口规范、Mock 规范和开发约定，作为前端、后端、测试和产品进行研发对接的共同依据。

业务范围与交互验收以 [需求说明](./需求说明.md) 为准；本文档不重复定义产品需求。

## 4. 运行环境

### 4.1 Node.js

项目要求 Node.js `>=20.19.0`。当前电脑的全局 Node.js 版本较旧，因此项目在以下目录提供独立运行时：

```text
AMR_v2/.runtime/node
```

`.runtime` 已加入 `.gitignore`，不会提交到仓库。新终端进入项目后执行：

```bash
export PATH="$PWD/.runtime/node/bin:$PATH"
node --version
npm --version
```

预期 Node.js 版本为 `v24.19.0`。团队其他成员可使用满足版本要求的本机 Node.js，不要求提交或共享 `.runtime`。

### 4.2 常用命令

```bash
npm install
npm run dev
npm run type-check
npm run build
npm run preview
```

开发服务默认地址：`http://127.0.0.1:5173`。

```text
┌──────────────────────────────────────────────────────────────┐
│ Views / Layouts                                              │
│ 一级页面、页面框架、路由入口                                  │
├──────────────────────────────────────────────────────────────┤
│ Features / Components                                       │
│ 实时监控、任务管理、AMR、交通、行为监控、地图与系统设置         │
├───────────────────────┬──────────────────────────────────────┤
│ Pinia Stores          │ Composables                          │
│ 全局上下文、实体缓存   │ 页面编排、订阅生命周期、交互复用       │
├───────────────────────┴──────────────────────────────────────┤
│ Domain API / Realtime Adapter                               │
│ HTTP 业务接口、实时事件适配、数据标准化                        │

```

依赖方向只能自上而下。展示组件不得直接读取 Mock 文件、调用 Axios、创建 WebSocket 或依赖后端原始字段。

```text
│  ├─ components/           # 无明确业务归属的通用组件
│  ├─ features/

│  │  ├─ amrs/
│  │  ├─ traffic/
│  │  ├─ behavior/
│  │  └─ alarms/
│  ├─ layouts/              # 一级导航、账号入口和页面容器

│  ├─ types/                # 公共领域类型与接口类型

├─ .env.production

└─ vite.config.ts
```

业务功能优先放入 `features`，并在功能内部维护组件、组合函数和局部类型。只有被多个领域使用的组件才进入 `components`。

当前业务边界进一步约束如下：

- `digital-twin` 只消费运行快照，不承担历史任务查询；
- `task-records` 通过独立 API 读取任务归档；
- `behavior` 的模板列表、编辑器和运行监控分别建模，共享类型但不共享页面状态；
- `resources` 的列表、详情和地图编辑器使用独立路由页面，公共数据访问集中在资源 API，不在页面间复制 Mock；
- 地图编辑状态不得写入实时监控 Store，发布成功后通过资源版本刷新机制通知运行模块。
- 地图列表数据统一通过 `src/api/modules/resources.ts` 获取；地图草稿读取、保存、校验和发布统一封装在 `src/api/modules/maps.ts`，页面不得直接引用 Mock 文件。
- 首期地图编辑模拟数据存放于 `mock/data/map-editor.ts`，按地图编号组织点位、路线、已放置资源和管制区域；切换真实后端时保持页面调用契约不变。
- 全局运行范围由 `stores/runtimeScope.ts` 统一维护，实时监控、任务管理、行为树管理、地图管理和资源管理均以 `scopeId` 作为查询上下文；各页面不得自行维护互不相干的范围状态。
- 地图实体采用“运行范围 + 地图版本”模型。同一 `scopeId` 下允许存在一个运行版本和多个车辆上传或人工导入的草稿版本，地图版本不等同于新的运行区域。

## 7. 页面与路由

页面使用一套可折叠左侧导航。路由层级与菜单层级解耦：菜单最多两层，详情页可继续使用更深的路由层级，但不增加菜单层级。

当前路由：

| 路径 | 页面 | 说明 |
| --- | --- | --- |
| `/` | 实时监控 | 默认首页 |
| `/task-records` | 任务管理 | 当前任务与历史任务统一查询入口，聚合交通、行为和告警 |
| `/resources/amrs` | AMR 列表 | AMR 实例与详情入口 |
| `/resources/amr-models` | AMR 型号 | 型号参数维护 |
| `/resources/devices` | 设备列表 | 设备与详情入口 |
| `/resources/device-types` | 设备类型 | 设备类型维护 |
| `/maps` | 地图管理 | 独立一级入口，承载地图列表与编辑入口 |
| `/behaviors` | 行为树管理 | 行为树及子树模板列表与编辑入口 |
| `/settings/users` | 用户管理 | 用户与角色入口 |
| `/settings/roles` | 角色权限 | 权限配置 |
| `/settings/configurations` | 配置管理 | 平台配置 |
| `/settings/dictionaries` | 数据字典 | 统一状态字典 |
| `/settings/operation-logs` | 操作日志 | 人工操作记录 |
| `/settings/system-logs` | 系统日志 | 系统问题定位 |

系统设置数据访问统一封装在 `src/api/modules/settings.ts`，模拟数据存放于 `mock/data/settings.ts`。用户、角色、配置、字典和日志视图不得直接依赖 Mock；操作日志与系统日志共享查询和详情视图，但保持不同数据类型与字段契约。

详情优先使用路由参数或查询参数保存上下文，例如：

```text
/?taskId=TSK-001
/?amrId=AMR-03
/task-records/TSK-001
```

允许分享和刷新后恢复的状态应进入 URL；临时面板开合、悬停对象等短生命周期状态不进入 URL。

### 7.1 菜单配置

当前菜单由 `AppLayout.vue` 中唯一的类型化配置数组生成，后续接入权限接口时可迁移为独立配置模块。数据结构为：

```ts
interface NavigationItem {
  id: string
  label: string
  icon: string
  route?: string
  children?: NavigationItem[]
  permission?: string
}
```

- 无 `children` 的项目点击后直接导航；
- 有 `children` 的项目只控制展开状态；
- 分组展开状态与导航收起状态由布局 Store 维护；
- 当前路由通过 `route.meta.menuId` 和 `route.meta.groupId` 映射到菜单；
- 权限过滤在生成最终菜单树之前执行；
- 详情页通过路由元数据指向来源菜单，确保刷新后仍正确高亮。

## 8. 状态管理

### 8.1 状态分类

| 状态类型 | 存放位置 | 示例 |
| --- | --- | --- |
| 服务端实体 | API 缓存或领域 Store | Task、AMR、Alarm |
| 页面全局上下文 | Pinia | 当前地图、任务、AMR、事件 |
| 实时连接状态 | Pinia | connected、lastUpdatedAt、retryCount |
| 组件临时状态 | 组件内部 | 页签、折叠、悬停、输入内容 |
| 可分享状态 | Router | 选中任务、选中 AMR、历史时间范围 |

### 8.2 实时监控上下文

建议状态结构：

```ts
interface MonitorContext {
  scope: {
    siteId: string | null
    floorId: string | null
    mapId: string | null
  }
  selectedTaskId: string | null
  selectedAmrId: string | null
  selectedEventId: string | null
  mode: 'realtime' | 'history'
}
```

任务、AMR 和事件的选中关系由 Store action 统一维护，组件不得分别修改多个 ID 形成不一致状态。

## 9. 接口架构

### 9.1 分层规则

```text
Vue Component
  → feature service / store action
  → domain API
  → shared HTTP client
  → real backend or mock handler
```

组件不得导入 `axios`。业务接口不得返回 AxiosResponse，而应返回业务数据类型。

### 9.2 统一响应

```ts
interface ApiResponse<T> {
  code: string
  message: string
  data: T
  traceId?: string
  timestamp: string
}

interface PageResult<T> {
  items: T[]
  page: number
  pageSize: number
  total: number
}
```

后端返回结构未最终确认前，由适配层将后端字段转换为上述前端标准结构。页面不得兼容多种响应格式。

### 9.3 HTTP 客户端职责

`src/api/http.ts` 负责：

- `baseURL` 和超时；
- 身份信息与通用请求头；
- Trace ID 透传；
- 请求取消；
- 401、403、业务错误和网络错误分类；
- 响应解包；
- 可观测日志钩子。

不得在 HTTP 客户端中加入任务、车辆等领域逻辑。

### 9.4 业务接口模块

建议拆分：

```text
taskApi       派单任务、任务详情、历史任务
amrApi        AMR 列表、状态和位置快照
trafficApi    路线、路段占用、资源锁和交通事件
behaviorApi   行为实例、当前执行链和节点详情
dispatchApi   已发布调度策略、当前策略和 APS 启停
alarmApi      告警列表、确认和详情
mapApi        地图定义、点位和逻辑图层
```

接口方法以业务动作命名，如 `getActiveTasks()`、`getBehaviorExecution(taskId)`，避免使用 `queryData()` 等模糊名称。

### 9.5 首页数据来源

首页组件不直接决定数据来自真实服务还是 Mock。页面只调用领域 API 或 Store action，由适配层组合首次快照与实时增量。

| 首页数据 | 领域入口 | 首次加载 | 后续更新 | 主要关联键 |
| --- | --- | --- | --- | --- |
| 厂区、楼层、当前地图 | `mapApi` | HTTP | 切换范围后重新请求 | `scopeId`、`mapId` |
| 行为树与 AMR 绑定关系 | `behaviorApi`、`resourceApi` | HTTP | 打开绑定弹窗时读取，保存后刷新 | `behaviorTreeId`、`amrIds` |
| 地图边界、逻辑路网、节点 | `mapApi` | HTTP 快照 | 地图版本变化时刷新 | `mapId`、`mapVersion` |
| 首页 CNC、HOME 资源 | `mapApi` | HTTP 快照 | 资源配置变化时刷新 | `resourceId`、`mapId` |
| AMR 名称、IP、型号、底盘、服务设备和能力 | `amrApi` | HTTP 主数据 | 资料版本变化时刷新 | `amrId` |
| AMR 坐标、朝向、速度、电量和运行状态 | `amrApi` + `RealtimeAdapter` | HTTP 快照 | 高频位置与状态事件 | `amrId`、`sequence` |
| 选中 AMR 的当前任务、阶段和进度 | `taskApi` | 选中 AMR 后按需 HTTP | 任务状态事件 | `taskId`、`amrId` |
| 请求设备、规划路径、已走路径 | `taskApi` / `trafficApi` | 选中任务后 HTTP | 路线增量事件 | `taskId`、`deviceId`、`routeVersion` |
| 已发布调度策略与 APS 开关 | `dispatchApi` | 进入任务管理时 HTTP | 弹窗应用后重新请求待调度任务 | `strategyId`、`apsEnabled` |
| 当前行为执行链和节点状态 | `behaviorApi` | 选中任务后按需 HTTP | 行为节点事件 | `taskId`、`behaviorInstanceId` |
| 未确认告警数 | `alarmApi` | HTTP 快照 | 告警事件 | `alarmId`、`taskId`、`sourceId` |
| 任务历史事件时间轴 | `taskApi` | 进入任务管理详情后分页 HTTP | 不在首页常驻订阅 | `taskId`、`eventId` |

当前初版通过 `src/api/modules/operations.ts` 暴露 `getTwinSnapshot()`；当 `VITE_USE_MOCK` 不为 `false` 时，数据从 `/mock/data/operations.ts` 动态加载。Vue 组件不得直接导入 `/mock`。真实接口接入后保留相同的 `TwinSnapshot` 领域结构，或在 API 层完成后端 DTO 到领域模型的转换。

资源管理通过 `src/api/modules/resources.ts` 暴露 `getResourceCatalog()`，统一返回 AMR、CNC/HOME 设备、AMR 型号、设备类型和地图定义。Mock 模式下该接口组合 `/mock/data/operations.ts` 的运行主数据与 `/mock/data/resource-management.ts` 的配置主数据；真实模式预留 `GET /resources/catalog`。资源页面不得直接导入 Mock。

历史任务通过 `src/api/modules/task-records.ts` 读取 `/task-records`，Mock 数据位于 `/mock/data/task-records.ts`；任务管理页同时通过 `operations.ts` 读取当前运行任务，并在页面视图模型中组合展示，接口数据仍保持分离。调度设置通过 `src/api/modules/dispatch.ts` 读取和更新 `/dispatch/settings`，Mock 数据位于 `/mock/data/dispatch.ts`。行为树通过 `src/api/modules/behaviors.ts` 读取 `/behavior-trees` 与 `/behavior-trees/{id}`，Mock 数据位于 `/mock/data/behaviors.ts`。

`TaskRecord.result` 首期只允许 `已完成 | 已取消`。运行异常由任务执行域处理，归档接口不得返回“异常”作为终态。日期和结果筛选当前在 Mock 阶段由页面完成；真实接口接入后对应查询参数建议为 `result`、`startedFrom`、`startedTo`。

`BehaviorTreeDefinition.kind` 区分 `behavior | subtree`。新建弹窗只产生编辑上下文，正式保存需分别调用行为树或子树创建接口；编辑器的节点库、画布选择和属性表单属于编辑器局部状态，不写入首页监控 Store。

数据合并规则：

1. 首次进入或断线重连时先获取完整快照，再订阅增量事件；
2. 以实体 ID 建立缓存，以 `sequence` 或服务端版本拒绝重复、乱序和过期更新；
3. 任务、车辆、交通与行为通过 `taskId`、`amrId`、`behaviorInstanceId` 关联，不依赖显示名称关联；
4. 切换 `scopeId/mapId` 时取消旧范围订阅并清空旧选中对象，防止跨地图数据残留；
5. AMR 资料与高频运行状态分开缓存，位置更新不得覆盖名称、型号和服务范围等主数据。

## 10. 实时数据

### 10.1 数据频率分层

| 数据 | 建议更新方式 | 说明 |
| --- | --- | --- |
| AMR 坐标、速度、朝向 | WebSocket 或高频推送 | 建议 200–1000ms 高频增量数据，最终以后端能力为准 |
| 任务状态 | WebSocket/SSE | 状态变化事件 |
| 行为节点状态 | WebSocket/SSE | 节点进入、完成、失败 |
| 告警和交通事件 | WebSocket/SSE | 事件流 |
| 地图定义、资源台账 | HTTP | 低频快照 |
| 历史记录 | HTTP 分页 | 按需查询 |

最终传输方式由后端能力确定。前端通过统一 `RealtimeAdapter` 暴露订阅接口，页面不感知底层是 WebSocket、SSE 还是轮询。

### 10.2 事件信封

```ts
interface RealtimeEvent<T> {
  eventId: string
  eventType: string
  occurredAt: string
  sourceType: 'task' | 'amr' | 'traffic' | 'behavior' | 'alarm'
  sourceId: string
  taskId?: string
  sequence?: number
  payload: T
}
```

同一来源存在顺序要求时必须提供 `sequence`。前端需要忽略重复事件，并防止旧事件覆盖新状态。

### 10.3 断线策略

- 连接状态和最后成功更新时间保留在状态 Store，首页不直接展示；运行范围由顶部状态栏右侧的统一入口驱动；
- 断线后进行有限次数指数退避重连；
- 数据超过约定时限未更新时标记为“数据已过期”，不得继续显示为实时；
- 重连后先获取一次完整快照，再继续消费增量事件；
- 多标签页场景是否共享连接在性能验证阶段确定。

- 规划路径和已走路径；
- CNC、HOME 和 AMR；
- 基础逻辑路网及路口节点；
- 选中和平移；首页不提供缩放控件，缩放能力仅保留在地图编辑器。

地图编辑、SLAM、路径规划和调度算法不在前端实现。

### 11.2 技术选型要求

SVG、Canvas 或专业图形库需通过最小技术验证后确定，验证指标包括：

- 预计最大 AMR 数和点位数下的更新帧率；
- 高频位置更新是否只重绘变化对象；
- 图层开关和点击命中；
- 坐标系转换；
- 路线与轨迹绘制；
- 缩放后文字和图标可读性；
- 浏览器内存占用和长时间运行稳定性。

地图组件只消费标准化后的领域数据，不直接解析后端协议。

### 11.3 首页地图领域模型

```ts
interface TrafficSegment {
  id: string
  path: string
  status: 'clear' | 'occupied' | 'congested' | 'blocked'
  direction: 'one-way' | 'two-way'
  speedLimit: number
  occupantId?: string
  waitingCount?: number
}

interface TrafficZone {
  id: string
  type: 'intersection' | 'mutex' | 'restricted'
  status: 'available' | 'occupied' | 'waiting' | 'blocked'
  capacity: number
  occupantId?: string
  waitingCount?: number
}

interface AmrProfile {
  id: string
  name: string
  ip: string
  model: string
  chassis: string
  initialPoint: string
  serviceDevices: string[]
  serviceStations: string[]
  supportedActions: string[]
  ratedLoad: string
  connectedAt: string
}
```

`path` 是 API 层完成坐标转换后的绘制数据，不代表前端负责路线规划。后端若返回点列，统一由地图适配器生成 SVG Path 或 Canvas 指令。

### 11.4 图层与更新边界

地图从底到顶依次渲染：底图 → 逻辑路网 → 交通状态 → 资源 → 任务路径 → AMR → 交互标记。路网和资源为低频静态层，AMR 与交通状态为独立动态层；选中任务只更新任务路径和交互层，不应重建底图。

首页逻辑图复用原交通管控页的绘制风格并进一步精简：地图容器通过 CSS 多层线性渐变连续绘制 20px 次网格与 100px 主网格，SVG 只绘制路网、资源、车辆和选中路线。该结构避免 SVG 固定 `viewBox` 造成网格在宽屏或面板收起后出现边界与留白。不渲染地图底板、边界、区域名称、点位编号、占用区、交通状态区、缩放工具和坐标栏。资源层仅保留 CNC、HOME、AMR；选中对象时仅渲染规划路径与已走路径。

地图拓扑 `columns / rows / paths`、资源坐标、AMR 坐标和任务路径均属于接口数据。组件只负责渲染，不允许通过 `displayPositions`、`resourcePositions` 或按任务编号建立路径常量。选择 AMR 后，根据其 `serviceDevices` 与 `serviceStations` 计算服务资源集合并点亮对应 CNC/HOME；其余资源降级显示。

当前 Mock 使用 6 列 × 6 点位的数据集验证密集设备场景，设备编号按列递增；CNC-12、CNC-24、CNC-36 的点位由 HOME-01、HOME-02、HOME-03 替代，CNC-30 保持加工设备，资源总量为 33 台 CNC 与 3 个 HOME。6 台 AMR 以每两台共享相邻两列资源的方式提供演示数据；该关系保存在 Mock/API 返回的 AMR 主数据中，地图组件不得自行按坐标推断。默认地图不渲染常驻服务关系标记，只有选中 AMR 后才读取服务设备集合进行高亮。Mock 任务的请求设备、`plannedPath` 与 `traveledPath` 必须同时处于所分配 AMR 的服务关系和路网拓扑约束内；AMR-06 的当前路线以 HOME-03 为起点、CNC-31 为终点。

Mock 演示运动由 `features/digital-twin/useTwinSimulation.ts` 独立维护。模拟器不修改 Pinia 快照，只根据任务 `plannedPath` 计算显示坐标、切线朝向和归一化路线进度；地图使用同一进度绘制已走路径，对象检查面板读取同一显示坐标。真实接口接入后可停用模拟器并替换为 WebSocket 坐标流，地图组件契约保持不变。

对象检查面板维护独立的 `collapsed` 页面状态；面板收起时保留业务选择，只卸载详情内容并保留紧凑恢复入口。实时监控不设置派单任务侧栏，地图默认占用整个主工作区。路线图例固定在地图左上角，不依赖右侧面板定位。

地图平移使用 Pointer Events 统一支持鼠标与触控笔：指针按下时记录起点和当前偏移，移动时更新页面局部 `pan.x / pan.y`，释放或取消时结束拖拽。相同偏移同时用于 SVG `transform` 与容器 `background-position`，确保网格和业务图层同步。AMR 与浮层控件从拖拽起点中排除；拖拽状态不进入 Pinia，也不触发接口请求。

## 12. 行为监控

首页展示当前行为实例摘要和执行链，不直接渲染行为树模板结构。建议前端接收扁平执行轨迹：

```ts
interface BehaviorExecutionStep {
  nodeId: string
  nodeName: string
  nodeType: string
  status: 'pending' | 'running' | 'success' | 'failure' | 'waiting' | 'skipped'
  startedAt?: string
  endedAt?: string
  durationMs?: number
  reason?: string
}
```

行为监控直接在首页对象检查面板完成，不设置“打开完整监控”跳转。`/behaviors` 保持为行为树模板列表，为后续模板查看和编辑预留；模板数据与运行轨迹使用不同接口和状态，不得互相替代。

## 13. Mock 架构

### 13.1 原则

- 所有模拟业务数据只存放在 `/mock`；
- Mock 与真实服务共用 TypeScript 类型和接口契约；
- 页面通过业务 API 获取数据，不感知数据来源；
- 环境变量 `VITE_USE_MOCK` 控制启用状态；
- 场景切换不得要求修改 Vue 组件。

### 13.2 目录职责

```text
mock/data/          地图、AMR、设备等稳定实体
mock/scenarios/     正常运行、拥堵、故障等状态组合
mock/handlers/      将场景数据映射为 HTTP 与实时事件
```

### 13.3 首批场景

| 场景 ID | 内容 | 验证重点 |
| --- | --- | --- |
| `normal` | 多任务正常运行 | 全局态势和车辆移动 |
| `traffic-blocked` | 路段占用导致等待 | 任务、地图与行为等待联动 |
| `behavior-retry` | 节点失败后重试 | 行为监控和事件顺序 |
| `amr-fault` | AMR 故障 | 告警定位和数据过期 |
| `device-timeout` | 机台无响应 | 请求来源和等待原因 |
| `empty` | 无派单任务 | 空状态 |
| `api-error` | 接口失败 | 错误反馈和重试 |

## 15. 错误与日志

错误分为：

- 网络不可用；
- 请求超时；
- 未登录或登录过期；
- 无权限；
- 业务拒绝；
- 数据不完整；
- 实时连接中断。

界面向用户说明“发生了什么、当前数据是否可信、可以做什么”。开发日志不得输出令牌、密码、完整设备报文或敏感节点输入输出。

## 16. 性能约束

- 地图对象更新不得触发整个页面重新渲染；
- 位置数据在进入 Store 前进行批处理或节流；
- 任务和事件列表为长列表预留虚拟滚动；
- 对象检查面板按选择加载详细数据；
- 完整行为树按需加载；
- 页面隐藏后降低或暂停非必要动画；
- 长时间运行测试至少覆盖断线、重连、场景切换和持续位置更新。

具体数量和性能指标需等待后端提供 AMR、任务、地图点位和事件频率上限。

## 17. 测试与质量门槛

计划引入：

- 单元测试：状态转换、格式化和坐标转换；
- 组件测试：任务选择、面板切换、空状态和错误状态；
- 集成测试：任务、车辆、地图、行为监控联动；
- 端到端测试：异常发现到定位的完整路径；
- 长时间运行测试：实时连接、内存和状态一致性。

每次交付至少执行：

```bash
npm run type-check
npm run build
```

后续配置测试与代码检查工具后，再将对应命令加入持续集成。

## 18. 安全约束

- 身份令牌不得写入源码、Mock 或仓库；
- 高风险操作必须由后端再次鉴权；
- 前端权限控制只负责界面可见性，不作为安全边界；
- 服务端返回的节点输入输出需按权限脱敏；
- 页面内容按普通文本渲染，禁止直接注入未清洗 HTML；
- 依赖升级需要检查安全公告和破坏性变更。
