# AMR_v2 需求说明

> 文档状态：开发基线稿
> 版本：V1.2
> 更新日期：2026-08-20
> 适用阶段：需求评审、研发对接、验收测试
> 项目定位：面向厂内物流场景的 AMR 数字孪生运行平台

## 1. 项目背景

AMR_v2 用于呈现厂内 AMR 物流系统的实时运行状态。平台以 2D 数字孪生地图作为主要工作界面，将任务、车辆、路径、交通资源、行为监控、设备信号和告警组织在同一运行上下文中，帮助现场人员快速判断整体状态并定位异常原因。

任务不由用户创建或维护。机台上抛请求后，后端负责识别请求、解析任务类型、创建任务实例，并根据任务类型自动匹配对应行为树。前端负责展示这一自动执行过程、运行状态和异常原因，不提供任务类型配置、任务模板配置或任务与行为树映射配置。

## 2. 建设目标

### 2.1 核心目标

1. 用户进入一个页面即可判断当前运行是否正常。
2. 用户选择任务、车辆或告警后，所有监控区域同步切换上下文。
3. 用户无需跳转页面即可完成常见异常定位。
4. 全站使用一套最多两层的折叠式左侧导航，不叠加第二套导航系统。
5. 前端使用 Vue 构建，为后续真实接口接入、组件复用和状态联动提供基础。
6. 所有服务请求通过统一接口层调用，页面组件不得直接拼接请求地址。
7. 模拟数据集中存放于 `/mock`，可在不修改页面逻辑的情况下切换真实接口。
8. 产品界面不提供任务手工创建、任务类型维护、任务模板配置或行为树人工匹配入口。

### 2.2 非目标

本阶段不实现以下能力：

- AMR 调度算法、路径规划算法和交通管制算法；
- 行为树运行引擎；
- SLAM 建图、定位和地图编辑算法；
- 真实设备通信、中间件协议或后端服务；
- 大规模数据压测和生产环境部署；
- 复杂调度规则编辑、策略编排和 APS 参数配置页面；任务管理仅提供已发布调度策略选择及 APS 启停。
- 面向最终用户的接口目录、接口调试工具和调试记录。

## 3. 用户与使用场景

### 3.1 主要用户

| 用户 | 主要诉求 | 默认权限建议 |
| --- | --- | --- |
| 现场人员 | 查看运行态势、处理告警、暂停或恢复任务 | 监控、处置、有限控制 |
| 研发人员 | 定位任务、行为树和交通执行问题 | 监控、诊断、调试 |
| 管理人员 | 查看整体效率、异常和任务完成情况 | 总览、只读 |
| 只读用户 | 查看指定范围的实时状态和历史记录 | 只读 |

### 3.2 核心场景

#### 场景 A：日常值守

用户进入实时监控首页，通过全幅 2D 地图查看车辆位置、运行状态和选中车辆的当前任务；待调度任务和全量任务统计进入任务管理查看。

#### 场景 B：任务异常定位

用户点击异常任务，地图定位车辆与路线，行为树定位当前失败或阻塞节点，事件时间轴展示相关交通事件、设备响应和告警。

#### 场景 C：交通阻塞定位

用户点击地图上的拥堵路段或资源锁，系统列出受影响任务和车辆，并展示相关行为树等待节点。

#### 场景 D：行为树执行诊断

用户点击运行中的行为树节点，查看节点状态、持续时间、输入输出摘要和关联地图对象；需要完整调试时再进入专业详情。

## 4. 产品结构

### 4.1 导航原则

- 全站只使用一套左侧主导航，不再同时设置顶部模块导航和独立二级侧栏。
- 左侧栏采用“直接入口 + 分组折叠”的树形结构，最多展示两层。
- 实时监控、任务管理、行为树管理和地图管理是独立直接入口；页面数量较多的业务域使用可展开分组。
- 同一时间只建议展开一个分组；当前页面所属分组保持展开。
- 导航展开宽度建议为 216–224px，收起宽度为 56px；实时监控首页允许收起导航以释放地图空间。
- 导航收起后只显示一级分组图标；需要访问分组内页面时，通过悬浮菜单或先展开侧栏操作。
- 详情页、创建页、编辑页不进入导航，通过列表、按钮或对象检查面板进入，并提供面包屑返回。
- 用户权限控制菜单和入口可见性，无权限分组不显示。

### 4.2 菜单结构

```text
实时监控                       # 默认入口
任务管理                       # 当前与历史任务统一入口
行为树管理                     # 行为树及子树维护
地图管理                       # 地图列表与编辑入口

资源管理                       # 可折叠分组
├─ AMR 列表
├─ AMR 型号
├─ 设备列表
└─ 设备类型

系统设置                       # 可折叠分组
├─ 用户管理
├─ 角色权限
├─ 配置管理
├─ 数据字典
├─ 操作日志
└─ 系统日志
```

以下页面不出现在左侧菜单：

- 任务详情；
- AMR、设备和地图详情；
- 地图编辑器；
- 行为树编辑器；
- 用户、角色、配置等创建或编辑页面。

说明：

- “任务管理”统一展示当前执行任务和历史任务；实时监控不重复展示派单任务队列，通过点击地图 AMR 查看其当前任务。
- 不提供任务配置、任务类型配置和手工派单入口。机台请求到达后，由后端自动解析并生成任务。
- 当前任务的行为监控直接在首页对象检查面板展示，不提供二次跳转。一级菜单“行为树管理”进入行为树模板列表，与运行监控相互独立。
- 车辆与交通实时状态在“实时监控”首页查看；与任务有关的交通事件、告警和行为节点记录统一进入任务管理，不分别设置记录菜单。
- 未关联具体任务的系统异常进入系统日志；是否需要独立告警中心根据后续实际告警量再评估。
- 不设置“接口调试”菜单，接口联调能力属于研发工具链，不进入正式产品信息架构。

### 4.3 任务管理范围

任务管理以任务实例为查询主键，同一列表展示当前任务与历史任务；一条任务聚合完整执行上下文：

- 请求来源和后端识别的任务类型；
- 分配的 AMR；
- 请求设备、规划路线和实际轨迹；
- 匹配的行为树名称与版本；
- 行为节点执行过程；
- 任务期间发生的交通等待、资源占用和重规划事件；
- 关联告警；
- 从请求到完成或失败的统一时间轴；
- 任务结果和各阶段耗时。

任务管理列表承担当前与历史任务查询，详情页负责诊断。首期不建设独立交通记录和告警记录页面。

任务管理页通过任务运行快照与历史任务接口组合统一列表；当前任务结束后从运行快照移除并进入历史数据。实时监控首页不重复展示派单任务列表，未分配 AMR 的任务统一在任务管理中查看。

任务运行期间发生的异常属于当前过程状态，不作为历史记录的最终结果。异常处理成功后任务归档为“已完成”；无法继续、人工终止或设备撤销请求时归档为“已取消”。任务管理提供进行中状态、具体运行状态及“已完成 / 已取消”结果筛选，并提供今日、近 7 天、近 30 天和全部日期筛选。列表不展示结果说明小字、行为树列和操作列；首期不提供逐行查看详情按钮。

任务总览将时间范围作为总览级筛选条件，任务总数、已完成和已取消随所选时间范围同步变化。实时任务按“待调度 / 运行中 / 异常”展示；任务执行过程中的等待状态归入运行中统计，不单独设置“等待中”总览字段。时间范围位于页面标题区，不设置单独的“任务总览”标题栏；状态筛选和关键词搜索位于任务列表工具栏。任务列表每页展示 10 条，底部提供总数、每页条数、页码及前后翻页；待调度使用黄色、运行中使用蓝色、异常使用红色、已完成使用绿色、已取消使用中性灰色。

### 4.3.1 行为树维护

行为树列表通过“行为树”和“子树”两个互斥页签分别管理，不提供“全部”混合视图，默认进入行为树页签。列表展示编号、类型、名称、流程摘要、版本、发布状态和更新时间，不展示引用字段，不提供状态筛选，仅保留关键词搜索。行为树行提供“绑定”操作，弹窗列出资源管理中的 AMR，可多选允许执行该行为树的车辆；子树不能独立执行，因此不提供绑定操作。新增时只选择行为树或子树并填写名称，不在创建步骤匹配任务类型；行为树可独立执行，子树只封装可复用流程。

编辑页面复用原项目的操作逻辑，并以 Vue 组件化实现“节点库 / 网格画布 / 节点属性”三栏工作台：节点库可在已发布子树和基础节点之间切换；节点支持拖拽进入画布、选中、连线和删除；属性面板支持修改名称、类型、目标对象、超时时间和失败策略；画布支持缩放；顶部提供保存草稿、结构校验和发布。存在未连接节点时不得发布。

### 4.3.2 资源详情与地图编辑

- AMR 列表进入独立详情页，详情展示车辆资料、型号参数和 CNC/HOME 服务关系，不展示“支持动作”。
- 设备列表进入独立详情页，展示设备资料、地图点位和反向关联的服务 AMR。
- 地图管理采用地图卡片库，卡片呈现地图缩略图、楼层、来源、运行版本、编辑版本和状态。
- 地图编辑采用工具轨、中央地图画布和对象属性面板，不使用普通表格行内编辑代替专业编辑工作台。
- 地图卡片支持按名称、编号或专案搜索，并可按发布状态与底图来源筛选；点击卡片进入编辑器，卡片独立操作入口用于维护基础资料、扫描底图、适用 AMR、现场设备与版本信息。
- 运行范围为全系统共享上下文。地图管理仅展示当前运行范围所属区块的地图版本，不将不同上传车辆或不同版本误表示为不同厂区地图。
- 同一运行范围可存在一个当前运行版本及多个草稿、候选或车辆上传版本；版本条目需展示版本号、上传车辆、上传时间、发布状态和逻辑对象差异。
- 地图管理不提供脱离当前范围的“创建新区域”操作，入口统一命名为“导入地图版本”，可选择车辆上传记录或本地文件，并作为当前范围的草稿导入。
- 地图编辑器延续专业工作台交互：左侧提供选择、新建点位、放置资源、创建路线、绘制管制区和删除工具；中央支持底图、逻辑图与叠加视图以及缩放；右侧根据当前工具显示对象属性或分步操作面板。
- 创建路线必须依次选择两个已有导航点位，再配置通行方向与最高速度；放置资源建立资源与作业点的空间关系；绘制管制区通过两个角点确定范围。
- 保存草稿、地图校验和发布地图为独立动作；未保存状态、坐标、缩放比例、校验错误与待确认项在编辑器状态栏持续反馈。

### 4.3.3 系统设置

- 用户管理支持按用户名或姓名搜索，并按角色、启用状态筛选；支持新增和编辑用户，用户名作为稳定账号标识。
- 角色权限采用系统固定角色，不允许前端任意新增或转授车辆控制权限；页面需明确展示现场人员、研发人员和只读用户的操作边界。
- 配置管理按运行显示、任务设置、地图与车辆、界面设置分组维护，配置保存后必须写入操作日志。
- 数据字典支持分类查询、新增和编辑；系统运行状态字典不得直接删除，避免破坏历史数据和状态映射。
- 操作日志记录用户、模块、操作、对象、结果和说明；系统日志记录级别、服务、AMR、任务、Trace ID 和日志摘要。
- 两类日志均为只读页面，支持条件筛选和详情查看；系统日志详情需便于复制 Trace ID 进行跨服务排障。

### 4.4 导航交互规则

1. 点击“实时监控”直接进入首页，不展开子项。
2. 点击“任务管理”“行为树管理”或“地图管理”直接进入对应页面。
3. 点击资源管理或系统设置的分组标题展开或收起子菜单；展开动作本身不跳转页面。
4. 点击子菜单进入对应列表页，分组标题和子项同时显示选中状态。
5. 刷新页面后，当前路由所属分组自动展开。
6. 收起侧栏时保留当前一级分组的选中标记；悬浮图标显示分组名称和子菜单浮层。
7. 详情页仍高亮其来源列表，例如 AMR 详情保持“资源管理 / AMR 列表”选中。
8. 一级分组使用独立图标，二级页面不使用字母缩写图标，避免菜单视觉噪声。

### 4.5 自动任务生成链路

```text
机台上抛请求
  → 后端校验并解析请求
  → 识别任务类型
  → 自动创建任务实例
  → 根据任务类型匹配行为树
  → 分配 AMR 并开始执行
  → 实时监控页面展示当前执行过程，任务管理归档完整生命周期
```

前端需要展示“请求来源、识别出的任务类型、匹配的行为树及版本”，用于解释系统为什么执行当前行为，但这些字段在监控页面中均为只读。

## 5. 实时监控首页

### 5.1 页面定位

实时监控是系统默认入口，页面的唯一核心任务是：让现场人员在不离开地图的情况下看清全局运行状态，并完成从异常发现到原因定位。

首页存在两种明确状态：

- `全局态势`：未选择具体对象，观察当前范围内全部任务、AMR 和交通状态；
- `对象检查`：选择任务或 AMR，查看与该对象关联的任务、路线、行为监控和车辆资料。

### 5.2 布局方案

```text
┌──────┬─────────────────────────────────────────────────────────────┐
│ 一级 │ 上线·可运行 │ 执行·空闲·等待·充电·异常 │ 运行范围 │
│ 导航 ├─────────────────────────────────────────────────────────────┤
│      │ 规划路径·已走路径                                           │
│      │             2D 数字孪生地图                                 │
│      │             AMR / 路线 / 交通资源 / 异常                     │
│      │                                                             │
│      └─────────────────────────────────────────────────────────────┤
└──────┴─────────────────────────────────────────────────────────────┘
```

地图占据首页状态栏下方的整个主工作区，是页面的视觉中心和操作底板。车队连接与调度能力、车辆运行状态采用贯穿页面的单行顶部状态栏分组展示，运行范围位于状态栏右侧。行为执行过程不固定占栏，只在用户选择 AMR 后打开右侧检查面板。

建议在 1920×1080 下采用以下尺寸基线：

| 区域 | 建议尺寸 | 说明 |
| --- | --- | --- |
| 一级导航 | 展开 176px，收起 56px | 默认可收起 |
| 顶部状态栏 | 约 60–64px 高 | 左侧展示 AMR 状态，右侧放置运行范围 |
| 对象检查面板 | 420–480px 宽 | 选择对象后从右侧覆盖打开 |
| 地图 | 剩余全部空间 | 不出现页面级纵向滚动 |

#### 5.2.1 信息分层

首页采用三级信息优先级，而不是给所有数据相同的视觉重量：

**一级信息：必须持续可见**

- 2D 地图及 AMR 实时位置；
- 上线车辆与可运行车辆数量，以及可运行车辆中的执行、空闲、等待、充电和异常数量；
- 未确认告警和交通阻塞。

**二级信息：选择对象后显示**

- 当前任务完整信息；
- AMR 电量、速度、位置和连接状态；
- 当前行为执行链、运行节点和阻塞原因；
- 规划路线、已行驶轨迹和相关交通资源；
- 车辆型号、网络信息、服务设备和服务站点。

**三级信息：明确请求后显示**

- 行为节点输入输出；
- 完整行为树结构；
- 详细告警上下文和 Trace ID；
- 历史事件和轨迹回放。

推荐布局：

```text
默认全局态势
┌────────────────────────────────────────────────────────┐
│                    2D 数字孪生地图                      │
│                                                        │
└────────────────────────────────────────────────────────┘

选择 AMR 或任务后
┌──────────────────────────────────────┬─────────────────┐
│ 2D 地图                              │ 对象检查面板      │
│ 车辆/路线/资源同步高亮                │ 概况/行为/车辆    │
└──────────────────────────────────────┴─────────────────┘
```

不建议使用以下方案：

- 在首页完整平铺任务表、行为树、交通地图和 AMR 列表；
- 同时展示多台车辆的完整行为树；
- 用多个同等醒目的统计卡占据地图空间；
- 依靠页面滚动查看实时监控，因为滚动后会丢失整体态势。

#### 5.2.2 对象检查面板

点击地图车辆后，右侧打开对象检查面板。面板使用覆盖方式进入，不触发页面跳转；地图视口自动平移，确保目标车辆不被面板遮挡。面板支持独立收起，收起时保留当前任务和 AMR 选择，地图恢复完整宽度；地图右侧保留紧凑的“展开详情”入口。面板分为两个页内标签：

1. `任务执行`：一张任务主卡统一展示任务编号、状态、任务类型、请求设备、行为树名称和任务进度；主卡下方直接展示行为节点执行轨迹，不再重复设置“行为监控”摘要卡。
2. `车辆信息`：车辆身份卡展示 AMR 名称、型号、底盘、额定载荷和最近连接时间；电量独立强调；实时信息仅保留 `(x, y)` 坐标与速度。服务范围允许在厂家标定的最大 CNC 集合内缩减，点亮表示启用、置灰表示停用。页面底部提供“暂停接单 / 恢复接单”操作，变更前必须二次确认。

标签用于切换同一个选中对象的详情，不属于系统二级菜单。异常发生时，面板自动优先打开与异常相关的标签，但不应在无用户操作时频繁弹开或切换。

“最近事件”不在对象检查面板重复展示。行为节点的执行顺序已经由“行为监控”表达；交通、设备、告警等历史事件统一归入对应任务的任务管理详情，避免同一过程在首页出现两套时间序列。

首页行为监控采用“执行轨迹”表达，不在窄面板中缩放完整树形图：

```text
已完成节点 → 已完成节点 → 当前节点 → 下一节点
                              ├─ 等待原因
                              └─ 已持续时间
```

行为监控无需“查看完整结构”或“打开完整监控”入口。首页面板直接展示当前运行链、节点状态、耗时和阻塞原因；行为树模板列表仅用于后续查看或编辑模板，不作为运行监控的详情入口。

#### 5.2.3 任务联动与调度入口

实时监控首页不设置派单任务队列。任务允许处于“已生成但未分配 AMR”的待调度状态，此类任务统一在任务管理列表中展示为“待调度 / 待分配 AMR / 等待车辆分配”。点击地图上已分配任务的 AMR 后，对象检查面板读取并展示其当前任务。

调度策略放置在任务管理页标题区，通过“调度策略”按钮打开弹窗。该弹窗允许：

- 从后端已发布策略中选择当前调度策略，例如规则优先、距离优先、负载均衡；
- 开启或关闭 APS 辅助排程；
- 查看当前 APS 启用状态；
- 应用设置后影响后续待调度任务，不在前端编辑策略规则或 APS 参数。

#### 5.2.4 AMR 顶部状态栏

首页采用单行顶部状态栏，不拆分为多张 KPI 卡。状态栏按两个维度分组：

```text
上线 6/6｜可运行 6  │  执行 2｜空闲 1｜等待 1｜充电 1｜异常 1  │  运行范围
```

左侧能力组只展示上线车辆和可运行车辆；中间状态组展示可运行车辆的当前运行阶段。执行、空闲、等待、充电和异常数量之和应与可运行车辆数量一致。车辆执行“暂停接单”后继续计入上线车辆，但立即从可运行车辆和后方状态分布中移除；恢复接单后重新纳入。执行使用蓝色、空闲使用灰色、等待使用黄色、充电使用青色、异常使用红色。状态栏不展示暂停接单独立指标、稼动率、电量分布、车辆明细、任务数量、交通阻塞或告警统计。

#### 5.2.5 异常呈现

- 首页不自动弹出普通事件；
- 异常车辆保持静止，并在车辆周围持续显示低透明度双层红色扩散光；
- 顶部状态栏通过“异常”状态数量提示，不增加独立告警或通知入口；
- 系统不得自动打开对象检查面板，避免值守过程中界面频繁跳动；
- 用户点击异常车辆后，地图选择态、任务路径和对象检查面板统一定位。

### 5.3 运行范围

当前运行范围设置在顶部状态栏右侧，作为全局上下文入口。首页不展示实时连接状态、最后更新时间、全局搜索和通知/告警入口。当前登录用户入口保留在左侧导航底部。

全局运行范围发生变化时，页面所有区域必须同步刷新，不允许每个监控区域重复设置地图或楼层筛选。

### 5.4 AMR 顶部状态栏

顶部状态栏首期只展示：

- 上线车辆数与当前运行范围的 AMR 总数；
- 可运行车辆数量；
- 可运行车辆中的执行、空闲、等待、充电、异常车辆数量；
- 右侧运行范围选择器。

口径约束：“上线车辆”以车辆心跳或长连接状态为准；“可运行车辆”表示车辆已上线、未被人工暂停接单，且后端运行许可为有效。前端优先使用后端 `runnable` 字段，不根据充电、异常等运行状态自行推断运行许可。后方五类状态只对可运行车辆分组统计，避免暂停车辆仍占用状态指标。

状态栏采用浅灰白背景与底部分隔线，状态名称和数字应保证远距离可读。规划路径与已走路径图例固定在地图左上角，不随右侧对象检查面板移动。

实时监控首期不设置底部车辆列表。当前车辆规模下，地图车辆即为主要选择入口，常驻底栏会压缩地图并与右侧车辆详情形成重复。后续当单一运行范围内车辆规模超过约 15–20 台、地图定位效率明显下降时，再评估增加可收起的车辆查找抽屉。

### 5.5 AMR 选择与详情

实时监控不设置派单任务队列。点击地图 AMR 后，右侧对象检查面板展示该车当前任务、行为监控与车辆资料；未分配 AMR 的任务统一在任务管理查看。

### 5.6 地图运行层

必须展示：

- AMR 当前位置、朝向和状态；
- 选中任务的规划路径和已走路径；
- CNC、HOME 和 AMR 三类运行资源；
- 基础逻辑路网。

对象交互：

- 点击 AMR：联动其当前任务、行为树和事件；
- 点击路段或交通资源：展示占用者、等待队列和受影响任务；
- 点击设备或站点：展示当前状态与关联任务；
- 点击告警标记：打开告警摘要并联动相关上下文。

地图编辑、坐标标定和复杂交通调试不直接放入实时监控首页，通过地图管理专业入口进入编辑器，避免值守页面承载高风险操作。

#### 5.6.1 图层结构

首页地图按固定顺序叠加，确保道路状态、任务路线和车辆不会相互遮挡：

1. `网格层`：由地图容器连续绘制并覆盖全部地图工作区，不受 SVG 比例或面板宽度影响，不增加地图边界、区域底板、名称或比例尺；
2. `逻辑路网层`：可通行路段和路口节点，不显示点位编号；
3. `资源层`：仅显示 CNC 和 HOME；
4. `任务路径层`：仅显示规划路径和已走路径；
5. `AMR 层`：位置、朝向、编号、运行状态和选中态。

地图表达对标原交通管控页，但进一步用于首页场景做减法：使用浅灰工程网格、细逻辑路网和紧凑资源标牌，不绘制独立地图背景、边界、区域名称、占用区、拥堵区或点位编号。默认不绘制所有任务路线；仅在选择任务或 AMR 后显示该对象的“规划路径 / 已走路径”。

地图工作区支持按住空白区域拖拽平移。拖拽时网格、路网、资源、车辆及已选路线必须同步移动；AMR 点击选择、面板按钮和路径图例不触发拖拽。左右面板展开或收起后，网格始终覆盖地图全部可见区域，不出现留白、断层或固定画幅边界。

#### 5.6.2 地图信息与交互细节

- 点击车辆后，仅显示该车当前任务的规划路径与已走路径，不显示其他任务路线。
- 选择 AMR 后，同时点亮该车服务范围内的 CNC 与 HOME；不在服务范围内的设备降为低对比度。
- 当前演示地图为 6 列 × 6 点位，共 36 个资源位置；其中 CNC-12、CNC-24、CNC-36 的点位分别配置为 HOME-01、HOME-02、HOME-03，CNC-30 恢复为加工设备，因此实际展示 33 台 CNC 与 3 个 HOME。AMR 每两台组成一组，共同服务相邻两列资源。
- AMR-01 空闲时停靠 HOME-01；当前 AMR-06 的执行中演示路线由 HOME-03 沿第六列路网前往 CNC-31。
- 每条任务模拟路线必须沿当前路网到达所属 AMR 服务列内的请求设备；任务请求设备不得落在该 AMR 的服务设备集合之外。
- 服务关系只在用户点选 AMR 后以设备高亮表达；默认地图不绘制服务括号、服务分区、AMR 服务标签或“服务关系”图例，避免展示真实接口尚未提供的常驻关系值。
- AMR 当前坐标必须落在路网上；存在运行任务时，当前位置必须与已走路径末端一致。
- 模拟环境仅允许“执行中”车辆沿任务规划路径循环移动；空闲、等待、充电和异常车辆保持静止。车辆坐标、朝向、任务进度与已走路径必须由同一个路线进度计算。
- 默认不显示任何任务路径；点击车辆后显示该车当前任务的完整规划路径与已走路径。执行中车辆的已走路径动态增长；等待中和异常车辆保持静止，并显示进入等待或异常时保存的静态已走路径。
- 选择 AMR 后，对象检查面板联动到其当前任务；右侧面板打开时地图自动平移，目标车辆不得被遮挡。
- 路线图例固定在地图左上角，不随对象检查面板开合移动，也不得放在右上角。
- 首页地图不显示运行地图名称、缩放工具、底部坐标或当前位置栏。
- 地图上的车辆位置均为只读监控数据，不允许在首页直接修改。
- 对象检查面板“当前位置”使用 `(x, y)` 坐标格式并保留两位小数，不再显示“主通道”“联络道”等位置文字。

### 5.7 行为监控

对象检查面板打开“行为监控”标签后展示：

- 行为树名称、版本和实例编号；
- 当前执行路径；
- 当前运行节点；
- 最近成功节点；
- 失败、等待或重试节点；
- 节点持续时间；
- 阻塞原因或结果摘要。

展示原则：

- 默认不完整展开大型行为树；
- 正常完成分支折叠，当前执行链和异常分支突出显示；
- 节点状态至少包含未开始、运行中、成功、失败、等待、跳过；
- 点击节点后展示节点输入、输出、开始时间、结束时间、耗时和关联对象；
- 行为监控全部在首页对象面板完成，不提供跳转按钮。

### 5.8 告警与任务事件时间轴

任务状态、行为树节点、交通事件、设备信号、AMR 状态和人工操作必须按任务归档到同一时间轴，以统一时间顺序展示。该时间轴位于任务管理详情，不作为首页对象检查面板页签；无法关联任务的系统级事件进入系统日志或告警详情。

事件至少包含：

- 发生时间；
- 事件类型；
- 事件级别；
- 事件摘要；
- 来源对象；
- 关联任务；
- Trace ID 或等效关联标识；
- 是否需要人工处理。

告警支持确认、查看详情和定位关联对象。高风险处置动作需二次确认并记录操作日志。

### 5.9 视觉设计规范

#### 5.9.1 设计方向

首页视觉主题定义为“厂内运行图纸”：以浅色工程图底板承载 2D 地图，用清晰的路径、资源占用和车辆状态表达实时变化。界面不使用传统深色大屏常见的霓虹边框、发光数字和装饰性图表，确保长时间值守仍具有良好可读性。

页面唯一的视觉焦点是数字孪生地图。其他区域使用低对比度容器，需要处理的异常才获得高饱和状态色。

#### 5.9.2 色彩基线

| 色彩角色 | 规范值 | 用途 |
| --- | --- | --- |
| 主蓝 | `#1677FF` | 执行中、选中对象、规划路径、主操作 |
| 深蓝 | `#0C5DCC` | 链接、深色强调和选中信息 |
| 青色 | `#00A6A6` | HOME 资源、充电状态和辅助运行强调 |
| 浅蓝 | `#55B7FF` | 品牌细节、路径辅助和浅色高亮 |
| 警告橙 | `#F59E0B` | 待调度、等待、拥堵和资源锁等待 |
| 成功绿 | `#20A66A` | 正常、在线、已完成 |
| 异常红 | `#D92D20` | AMR 异常、严重告警和失败节点 |
| 结构黑 | `#15202B` | 主文字和地图结构 |
| 深色侧栏 | `#101820` | 一级导航背景 |
| 中性灰 | `#8192A1` | 次级文字和空闲状态 |

颜色必须与文字、形状或图标共同表达状态。大面积背景仅使用白色与中性灰；高饱和色只用于运行对象、路径和需要处理的状态。

#### 5.9.3 字体规范

字体体系以项目《全局字体 UI 调整方案》为准：

- 中文首选 `Noto Sans CJK SC` / `Noto Sans SC`；
- 英文和数字首选 `Roboto`；
- 系统回退使用 `PingFang SC`、`Microsoft YaHei UI`、`sans-serif`；
- 生产环境使用本地 WOFF2 文件，不依赖公网字体 CDN；
- 只允许使用 400、500、700 三档字重；
- 编号、坐标、时间、电量和实时数据使用 Roboto 500，并启用等宽数字 `tabular-nums`。

| Token | 用途 | 字重 | 字号/行高 | 字间距 |
| --- | --- | ---: | ---: | ---: |
| Title | 页面标题、全屏编辑器标题 | 700 | 26px/35px | 1.5px |
| Headline 1 | 详情主对象、关键 KPI | 500 | 24px/33px | 1.5px |
| Headline 2 | 大卡片、关键分区标题 | 500 | 20px/27px | 1.5px |
| Body 1 | 说明文本、详情正文 | 400 | 16px/22px | 1.5px |
| Body 2 | 导航、按钮、输入框、表格正文 | 400 | 14px/19px | 1.5px |
| Compact | 表头、侧栏、属性面板、紧凑卡片 | 500 | 12px/17px | 0.4px |
| Caption | 更新时间、帮助文字、次级状态 | 400 | 10px/14px | 0.3px |
| Data | ID、版本、时间、电量、坐标 | 500 | 12px/16px | 0.4px |

关键业务文字不得低于 12px；10px 只用于辅助信息。地图画布中低于 10px 的空间标识不得承担关键业务含义。

#### 5.9.4 结构特征

页面的标志性设计元素是“对象检查轨”：用户选择任务或 AMR 后，任务卡、地图车辆、路线和右侧行为监控通过同一条运行蓝强调轨迹建立关联。该强调只服务于当前对象，不同时为多台车辆绘制高亮路线。

#### 5.9.5 动效约束

- AMR 位置更新使用短距离平滑过渡，不瞬移、不使用弹性动画；
- 异常车辆可使用低透明度双层红色扩散光提示，周期不得短于 2 秒，且不得缩放或闪烁车辆本体；
- 对象检查面板使用 160–220ms 的水平进入动画；
- 用户开启“减少动态效果”后取消平滑移动和脉冲；
- 不使用持续扫描线、背景粒子、无业务意义的数字跳动或装饰性呼吸动画。

## 6. 全局联动规则

### 6.1 全局上下文模型

实时监控首页需要维护唯一的页面上下文，至少包括：

- `scope`：厂区、楼层、地图；
- `selectedTaskId`：当前任务；
- `selectedAmrId`：当前车辆；
- `selectedEventId`：当前事件或告警；
- `timeMode`：实时或历史回放；
- `filters`：状态、类型、级别等筛选条件。

任何监控组件都通过全局上下文联动，不允许组件各自维护互相冲突的“当前任务”。

### 6.2 联动优先级

1. 用户明确点击的对象优先级最高。
2. 选择任务后，车辆、行为树和事件由任务关系自动确定。
3. 选择车辆时，若车辆有当前任务，则自动关联任务；无任务时只显示车辆上下文。
4. 选择告警或交通事件时，系统自动关联可识别的任务、车辆、节点和地图对象。
5. 用户清除选择后恢复当前运行范围的全局态势。

### 6.3 状态颜色约束

颜色语义全局统一：

| 状态 | 建议语义色 |
| --- | --- |
| 正常、成功、在线 | 绿色 |
| 运行中、执行中 | 蓝色 |
| 等待、警告、阻塞 | 黄色或橙色 |
| 异常、失败、故障 | 红色 |
| 未开始、离线、未知 | 灰色 |

颜色不得作为唯一状态表达，同时必须配合文字、图标或形状。

## 7. 历史回放与实时模式

首期至少预留实时/历史两种模式的数据模型和入口。

- 实时模式：持续接收状态更新，展示最新运行态势；
- 历史模式：选择任务或时间范围后，回放任务、轨迹、行为树节点和事件；
- 进入历史模式时必须有明显标识，避免用户误认为是实时数据；
- 历史模式中的暂停、恢复、封锁等实时操作必须禁用；
- 本轮原型可使用 mock 时间轴模拟回放，不要求实现真实流媒体或消息服务。

## 8. 技术实现约束

### 8.1 前端技术建议

- 框架：Vue 3；
- 开发方式：Composition API；
- 构建工具：Vite；
- 语言：建议 TypeScript；
- 路由：Vue Router；
- 状态管理：Pinia；
- 请求库：Axios 或基于 Fetch 的统一请求适配器；
- 样式：统一设计变量和组件级样式，具体 UI 组件库在视觉方案确定后选型；
- 图形能力：地图和行为树优先采用可维护的 SVG/Canvas 方案，具体库通过技术验证确定。

最终依赖版本在开发启动时锁定，本方案阶段不绑定具体小版本。

### 8.2 建议目录结构

```text
AMR_v2/
├─ Doc/                     # 需求、架构和研发约定
├─ public/                  # 不参与构建的静态资源
├─ mock/                    # 模拟数据、场景和模拟接口
│  ├─ data/                 # 基础模拟数据
│  ├─ scenarios/            # 正常、阻塞、故障等演示场景
│  └─ handlers/             # 模拟接口处理器
├─ src/
│  ├─ api/                  # 业务接口定义，组件不得绕过此目录
│  ├─ assets/               # 图片、字体和全局样式
│  ├─ components/           # 通用组件
│  ├─ features/             # 按任务、交通、行为树等领域组织
│  ├─ layouts/              # 页面框架和一级导航
│  ├─ router/               # 路由配置
│  ├─ stores/               # 全局状态与实时监控上下文
│  ├─ types/                # TypeScript 数据类型
│  ├─ utils/                # 无业务状态的工具函数
│  └─ views/                # 一级页面
├─ .env.development
├─ .env.production
└─ package.json
```

### 8.3 接口统一封装规则

1. 页面和展示组件不得直接调用 Axios、Fetch 或 mock 文件。
2. 所有请求由统一请求实例处理基础地址、超时、请求头、身份信息、取消请求和通用错误。
3. 业务接口按领域拆分，例如 `taskApi`、`amrApi`、`trafficApi`、`behaviorApi`、`alarmApi`。
4. 接口入参、返回值和错误结构必须有统一类型定义。
5. 真实接口与 mock 接口保持相同契约，切换时不修改页面代码。
6. 轮询、SSE 或 WebSocket 统一通过实时数据适配层接入，不直接散落在页面组件内。
7. 所有时间统一携带时区或使用约定的标准时间格式，展示层再进行本地化。
8. 接口错误必须区分网络错误、权限错误、业务错误和数据缺失。

统一接口封装是内部工程规范，不代表产品需要提供“接口调试”页面。

### 8.4 建议响应结构

```ts
interface ApiResponse<T> {
  code: string
  message: string
  data: T
  traceId?: string
  timestamp: string
}
```

列表接口统一返回分页信息；实时事件需包含唯一事件 ID、发生时间、来源类型、来源 ID 和关联任务 ID。

### 8.5 Mock 数据规范

`/mock` 是模拟数据的唯一存放位置，不在 Vue 组件内硬编码大段业务数据。

至少提供以下场景：

1. 全部正常运行；
2. 任务等待车辆；
3. 行为树节点失败并重试；
4. 路段拥堵导致任务等待；
5. 交通资源锁未释放；
6. AMR 离线或故障；
7. 设备无响应；
8. 多告警同时发生；
9. 空数据；
10. 接口超时或返回错误。

Mock 数据必须满足：

- 各模块通过相同 ID 建立真实关联；
- 时间顺序可支撑统一时间轴；
- 状态枚举与正式接口约定一致；
- 可通过环境变量启用或关闭；
- 可切换不同演示场景；
- 不包含真实账号、地址、密钥或生产数据。
- AMR、CNC、HOME、地图拓扑和任务路线使用同一坐标系，禁止组件内维护第二套显示坐标。
- AMR 服务设备关系同时供首页地图高亮、AMR 列表和设备列表反向查询使用。

## 9. 数据对象与关系

首期核心对象包括：

```text
任务 Task
├─ 分配一个 AMR
├─ 引用一个行为树实例
├─ 包含请求设备、规划路径与已走路径
├─ 关联多个交通资源事件
└─ 产生多个统一事件与告警

AMR
├─ 同一时刻最多执行一个主任务
├─ 位于一张运行地图
└─ 持续产生位置与状态

行为树实例
├─ 来源于行为树模板和版本
├─ 属于一个任务执行实例
└─ 包含多个节点运行记录
```

开发前必须统一任务状态、AMR 状态、节点状态、交通事件类型和告警级别枚举，避免各页面自行解释状态。

## 10. 权限与操作安全

- 查看权限与操作权限分离；
- 暂停任务、恢复任务、取消任务和直接控制车辆属于受控操作；临时封锁与解除资源锁延后评估，不在首期界面中提供；
- 高风险操作必须二次确认；
- 操作结果必须反馈成功或失败原因；
- 所有人工操作记录用户、时间、对象、操作前状态、操作后状态和 Trace ID；
- 只读用户不可看到可执行按钮，或按钮明确禁用并说明原因。

## 11. 非功能需求

### 11.1 性能

- 首屏应优先呈现整体运行状态，再加载非关键详情；
- 高频位置数据和低频业务数据分开更新；
- 地图对象更新不得导致整个页面重新渲染；
- 大型行为树默认按当前执行链加载或折叠；
- 任务、事件和告警列表需要支持虚拟滚动或分页扩展。

具体性能数值需根据预计 AMR 数、并发任务数、地图点位数和事件频率在技术评审中补充。

### 11.2 可用性

- 关键运行状态在常见桌面分辨率下无需滚动即可看到；
- 页面必须明确标识数据更新时间、断连和数据过期；
- 空数据、加载中、部分失败和断线重连均有明确反馈；
- 不依赖颜色作为唯一信息载体；
- 支持键盘焦点和基本可访问性。

### 11.3 可维护性

- 领域组件与通用组件分离；
- 页面展示逻辑与数据获取逻辑分离；
- 状态枚举、格式化方法和接口类型集中维护；
- Mock 与真实接口共用类型和契约；
- 任务、车辆和告警的展示模型与格式化逻辑集中复用。

## 13. 验收标准

### 13.1 产品验收

1. 系统使用单一左侧导航，实时监控为直接入口，其余页面通过一级入口或最多两层的折叠分组到达。
2. 实时监控提供全幅 2D 地图、AMR 全局状态和按车辆查看的行为监控，不重复展示任务列表。
3. 系统不提供任务手工创建、任务类型维护、任务模板配置或人工选择行为树入口。
4. 自动生成的任务可查看来源机台、解析后的任务类型及匹配的行为树版本。
5. 选择一个异常任务后，地图与行为监控同步定位相关内容，车辆信息显示所分配 AMR 的资料和服务范围。
6. 选择一个交通阻塞事件后，可以识别受影响任务、车辆和等待节点。
7. 行为树区域默认突出当前执行链，而非强制完整展示全部节点。
8. 用户可从实时监控首页选择 AMR，并在对象检查面板保留当前任务上下文。
9. 实时和历史模式有明确视觉区分。
10. 数据断开、加载失败和空数据均有清晰状态。
11. 正式产品不出现接口调试菜单。

### 13.2 技术验收

1. 项目使用 Vue 3、TypeScript 和 Vite 构建。
2. 组件不直接调用请求库或读取 mock 数据文件。
3. 所有业务接口通过 `/src/api` 或等效统一接口层暴露。
4. 所有模拟数据集中在 `/mock`。
5. Mock 和真实接口使用相同请求参数、响应结构和类型。
6. 可通过环境配置切换 mock 与真实服务，不修改业务页面代码。
7. 关键状态通过统一 Store 管理，监控组件不存在相互冲突的选中对象。
8. 至少覆盖正常、阻塞、节点失败、车辆故障、空数据和接口错误场景。

## 14. 待评审决策

以下问题需在原型设计或技术启动前确认：

1. 单一折叠侧栏的展开宽度最终采用 216px 还是 224px。
2. 实时监控首页主要面向 1920×1080 大屏值守，同时需要兼容普通办公显示器。
3. 实时监控不提供暂停、恢复或取消任务，也不提供临时封锁；仅允许在车辆信息中调整 CNC 服务范围，以及对 AMR 执行“暂停接单 / 恢复接单”。
4. 是否需要首期实现历史回放，还是只预留数据模型和交互入口。
5. 预计最大 AMR 数、并发任务数、地图点位数和事件更新频率。
6. 真实后端计划使用轮询、SSE、WebSocket 或混合方式推送实时数据。
7. 行为树节点输入输出中是否包含敏感参数，是否需要按角色隐藏。
8. 地图使用自研 SVG/Canvas、现有地图组件还是第三方图形库。
9. 行为树模板及其与任务类型的映射由当前平台维护，还是完全由后端或外部研发工具维护；若为后者，应取消行为树管理菜单。
10. 地图编辑器和系统日志页面已纳入当前前端范围，真实保存、发布和日志下载能力待后端接口确认。

## 15. 推荐推进顺序

1. 评审本需求文档，确认产品边界和左侧菜单树。
2. 确认一个典型异常闭环作为原型主线。
3. 以当前实时监控页面作为联动原型基线持续评审。
4. 确认数据对象、状态枚举和接口契约。
5. 输出视觉方案与高保真原型。
6. 当前 Vue 工程、统一 API 层和 Mock 场景已建立，后续补充真实接口契约。
7. 按“当前页面验收 → Mock 场景补齐 → 真实接口 → 联调测试”顺序推进。

建议首个演示闭环：`CNC 请求转运 → 任务派发 → AMR 行驶 → 交通资源等待 → 行为树等待节点 → 告警定位 → 资源释放 → 任务恢复并完成`。
